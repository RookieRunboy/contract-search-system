# Proposal: 字符级搜索高亮优化
- Status: Completed
- Created: 2025-12-16
- Author: Antigravity (AI assistant)
- Owners: Frontend Team
- Related Docs: openspec/project.md

## 问题陈述 (Problem Statement)
当前的搜索结果高亮机制使用的是严格的短语匹配逻辑 (`new RegExp('(${query})', 'gi')`)。
这意味着如果用户搜索 "高级大数据开发工程师"，但文档中包含的是 "大数据研发工程师"，系统无法高亮重叠的字符 "大数据" 和 "工程师"，因为中间的字符差异（"开发" vs "研发"）打断了短语匹配。

在中文搜索场景下，用户期望实现**字符级覆盖**（Character-level Coverage），即只要文档中的字出现在了搜索词中，就应该被识别为相关并高亮。当前的严格匹配降低了搜索结果的感知智能度和其实用性。

## 目标 (Goals)
- 更新前端高亮逻辑以支持**字符级匹配**。
- 确保文档中的任意字符如果存在于搜索查询中，都能被高亮显示。
    - 示例：查询 "开发"，文档 "研发" -> "发" 字高亮。
    - 示例：查询 "大数据开发"，文档 "大数据研发" -> "大数据" 和 "发" 字高亮。

## 非目标 (Non-Goals)
- 语义高亮（即高亮不共享字符的近义词）。
- 后端驱动的高亮（本提案仅关注纯前端渲染层的转换）。

## 解决方案概览 (Solution Overview)
我们将重构 `frontend/src/pages/SearchPage.tsx` 中的 `highlightText` 函数。

### 前端变更
1. **SearchPage.tsx**:
    - 将正则生成逻辑从 `new RegExp('(${query})', 'gi')` 更改为基于字符集的正则。
    - 从查询字符串中构建一个唯一字符的 `Set`（过滤掉空白字符和标点符号以减少噪点）。
    - 构建一个类似 `/(高|级|大|数|据)/gi` 的正则表达式。
    - 应用此正则来分割和高亮文本节点。

### 逻辑细节
- **输入**: 查询文本 "高级大数据"
- **处理流程**:
    1. 提取字符: `['高', '级', '大', '数', '据']`
    2. 构建正则: `/(高|级|大|数|据)/gi`
    3. 匹配文本: "大数据研发"
    4. 结果: "大", "数", "据"
- **优化**:
    - 将连续的匹配项合并为单个 `<span>` 块，以避免渲染过多的 DOM 节点（例如渲染 `<span class="highlight">大数据</span>` 而不是 `<span>大</span><span>数</span><span>据</span>`）。*注意：如果在分割时保留捕获组，React 的处理逻辑通常能自然处理这一点。*

## 风险与缓解 (Risks & Mitigations)
- **视觉干扰**: “停用词”或极其常见的字符可能会到处高亮。
    - *缓解措施*: 用户目前明确要求“简单”的实现。如有必要，我们可以后续添加停用字符过滤器。
- **英文/数字碎片化**: 搜索 "Java" 可能会高亮 "Banana" 中的 "a"。
    - *缓解措施*: 对于“简单高亮”的目标，这是可接受的。如果证明有干扰，我们可以在后续迭代中优化正则，使其在处理 ASCII 字符时尊重单词边界。

## 测试策略 (Testing Strategy)
1. **手动验证**:
    - 搜索长复合词组（如 "高级大数据开发工程师"）。
    - 验证包含变体（如 "大数据研发"）的文档是否显示部分高亮。
2. **边界情况**:
    - 验证查询中的特殊字符（如 `?`, `*`）是否会导致正则构建崩溃（必须转义字符）。
