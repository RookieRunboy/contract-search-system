# 智能标书解析与资质匹配模块 (Bid Analysis & Qualification Matching)

## 1. 背景与问题 (Background & Problem)

目前，公司解决方案部门在准备投标工作时，需要手动阅读冗长的招标文件（PDF），从中提取出关键的“投标人资格要求”或“类似业绩要求”（如：近三年单笔合同金额500万以上的金融类案例）。提取后，用户需要人工将这些要求转化为搜索关键词和筛选条件，在我们的合同系统中寻找证明材料。

这个过程存在以下痛点：
1.  **人工效率低**：标书篇幅巨大，人工寻找几行关键的业绩要求耗时费力。
2.  **搜索转化难**：用户难以将自然语言描述的业绩要求，精确转化为系统支持的组合筛选条件（金额范围、时间范围、分类等）。
3.  **响应速度慢**：在时间紧迫的投标周期内，无法快速评估我司是否有满足条件的存量合同。

## 2. 目标 (Objective)

构建一个“以标找合同”的智能辅助模块。用户上传标书文件（PDF），系统自动解析并提取其中的资质业绩要求，直接转化为合同搜索系统的筛选参数，实现**“上传即搜索”**的高效体验。

**核心价值**：从“人找合同”转变为“标书找合同”。

## 3. 解决方案 (Solution Description)

本方案不建立新的“标书数据库”，而是将标书解析作为搜索的**智能入口**。

### 3.1 核心流程
1.  **标书数字化（复用现有能力）**：
    *   用户在新的**“智能投标”模块**中上传标书 PDF。
    *   后端直接复用 `pdfToText.py` 中的 `MultiModalTextExtractor`（基于 Qwen-VL 等多模态模型），将 PDF 页面高效转化为大模型可读的纯文本。

2.  **智能提取与映射（新增逻辑）**：
    *   使用 LLM（DeepSeek V3）对文本进行分析。
    *   **Prompt 目标**：像投标经理一样思考，忽略商务废话，精准提取对“找合同”有用的硬性指标（资质要求、业绩要求）。
    *   **输出结构**：解析为标准的 `BidRequirements` 对象。

3.  **结果概览与确认（中间页）**：
    *   系统展示 **“解析结果概览页”**。
    *   显示提取到的关键红线条件：关键词、金额、时间、行业分类等。
    *   提供 **[人工修正]** 功能：用户可手动调整提取不准确的条件（如修改金额门槛、增删关键词）。
    *   *价值*：赋予用户控制感，确保后续搜索的准确性。

4.  **一键匹配合同（跳转）**：
    *   用户点击“匹配合同资质”按钮。
    *   系统携带确认后的参数，自动跳转到“合同检索”模块，并执行搜索，展示符合条件的合同列表。

### 3.2 数据提取映射规则 (Data Mapping)

LLM 将从标书中提取以下结构化数据，并映射为搜索参数：

| 标书原文示例 | 提取语义 | 系统搜索参数 |
| :--- | :--- | :--- |
| "投标人需具备承建过国有大型银行核心系统的经验" | 关键搜索词 | `query_text`: "国有银行 核心系统" |
| "单项合同金额不低于人民币 500 万元" | 金额下限 | `amount_min`: 5000000 |
| "提供近三年来的中标通知书或合同" | 时间范围 | `date_start`: "2022-01-01" |
| "项目案例需为金融、证券行业" | 行业分类 | `category_level1_filter`: ["金融"] |

## 4. 技术实现规划 (Implementation Plan)

### 4.1 后端改动
*   **新建 `BidAnalysisService`**：
    *   封装 PDF 处理与 LLM 交互逻辑。
    *   设计专用的 Prompt 模板，重点强化对数字（金额）、日期和行业名词的敏感度。
    *   *Future-Proof*: 为未来 RAG 对比功能预留接口结构。
*   **新增 API `POST /bid/analyze`**：
    *   接收 `UploadFile`。
    *   返回 `BidAnalysisResult` 对像（包含对应的 SearchParams）。

### 4.2 前端改动
*   **新增一级菜单【智能投标】(Smart Bidding)**：
    *   构建独立的模块入口。
*   **上传与解析页**：
    *   支持大文件上传与解析进度展示。
*   **解析结果确认页 (Dashboard)**：
    *   以卡片形式展示提取出的 5-6 个关键条件。
    *   支持表单编辑。
    *   底部“匹配合同”按钮，联动跳转到主搜索列表（携带 Query 参数）。

## 5. 后续验证 (Verification)

*   **测试用例 1**：上传一份真实的某银行招标文件，验证系统能否跳转至概览页，并正确提取出 `query_text` 和 `amount_min`。
*   **测试用例 2**：在概览页手动修改关键词后，点击跳转，验证合同检索页面是否使用了修改后的参数进行搜索。
