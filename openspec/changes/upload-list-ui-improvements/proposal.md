# 前端合同列表 UI 改进提案

## 问题描述
当前的上传页面 (`UploadPage.tsx`) 合同列表存在以下 UI 问题：
1. **合同名称截断**：长合同名称被省略号截断，限制了宽度，难以阅读完整名称。
2. **视觉干扰**：合同编码和 CIR 编码后的复制按钮过于显眼（"扎眼"），造成视觉干扰。
3. **命名不准确**：“CIR编码”应更名为“合同注册编码”。
4. **布局不合理**：表格列宽分配不科学，未根据内容长度优化。
9. **状态冗余**：存在“解析状态”和“原数据状态”两列，信息存在重叠，且占用过多水平空间。

## 解决方案

### 1. 合同名称完整显示
- 移除合同名称列的 `ellipsis`（省略号）和固定 `maxWidth` 限制。
- 允许文本自动换行，确保长名称能完整显示。

### 2. 交互优化：点击复制
- 移除 Ant Design 默认的 `copyable` 图标。
- 实现自定义交互组件 `ClickToCopy`：
  - 默认显示纯文本。
  - **悬停时**：显示微妙的边框轮廓和背景色，提示可交互。
  - **点击时**：自动复制内容到剪贴板，并显示“复制成功”提示。
- 应用于“合同编码”和“合同注册编码”两列。

### 3.用于字段重命名
- 将表格列头 "CIR编码" 重命名为 "**合同注册编码**"。

### 4. 布局科学化调整
- 重新调整各列宽度权重：
  - 给“合同名称”分配更多空间（或自适应）。
  - 给“状态”、“时间”等固定长度字段设置合适的固定宽度。

### 5. 状态列合并
- **合并字段**：将“解析状态”和“原数据状态”合并为单一的“状态”列。
- **展示逻辑**：
  - 优先展示处理过程中的详细状态（如：待解析、解析中、向量化中、元数据提取中）。
  - 如果解析失败，显示“解析失败”。
  - 如果所有步骤都成功（解析成功且元数据已提取），显示“已完成”。
  - 如果解析成功但元数据状态异常（如提取失败），显示“元数据异常”或在“已完成”状态上增加警告标识。
  - 简化列表视觉复杂度，避免两列状态造成的冗余。

### 6. 解析状态细化
- **现状**：目前并将“PDF转图片”和“图片转文本”统称为“正在解析”，用户无法感知具体进度。
- **改进**：
  -  backend拆分状态上报：
    - **PDF转图片中** (`parsing_images`): 当系统开始将PDF页面转换为图像时。
    - **图片识别中** (`parsing_ocr`): 当系统调用大模型或OCR引擎识别图片文字时。
  - frontend展示对应状态文案，让进度更透明。

  - 更新 `title`。

  - 更新 `render` 方法使用新组件。

- **合并状态列**：
  - 更新 `renderStatus` 方法，综合 `status` 和 `metadataStatus` 字段判断最终展示的文案和样式。
  - 移除 `metadataStatus` 列。
