# 文件重复检测功能提案

## 状态: IMPLEMENTED

## 概述

在文件上传时进行**文件名 + 内容哈希**双重检测，防止上传重复的合同文件。

## 背景

- 当前系统允许上传具有相同文件名或相同内容的文件
- 重复上传会浪费存储空间和处理资源
- 同一合同编码下可能有多个不同文件，因此不能仅依赖编码检测

## 检测策略

采用**双重检测**机制：

| 检测层 | 检测对象 | 检测方式 | 冲突处理 |
|-------|---------|---------|---------|
| 第一层 | 文件名 | 精确匹配 | 提示已存在同名文件 |
| 第二层 | 文件内容 | SHA256哈希 | 提示文件内容已存在（可能不同文件名） |

## 检测流程

```
用户上传文件
    ↓
[第一层] 检查文件名是否已存在于 uploaded_contracts 目录
    ├── 存在 → 添加到重复列表（原因：同名文件已存在）
    └── 不存在 → 继续
    ↓
[第二层] 计算文件内容 SHA256 哈希值
    ↓
查询 Elasticsearch 是否有相同哈希的文档
    ├── 存在 → 添加到重复列表（原因：相同内容已存在，显示原文件名）
    └── 不存在 → 允许上传
    ↓
返回检测结果，包含：
- 可上传文件列表
- 重复文件列表（含重复原因和原始文件信息）
```

## 后端变更

### 1. 新增字段存储

在 Elasticsearch 文档的 `document_metadata` 中添加 `file_hash` 字段：

```json
{
  "document_metadata": {
    "file_hash": "sha256:abc123...",
    ...
  }
}
```

### 2. 新增重复检测函数

在 `contractApi.py` 中新增：

```python
def _check_file_duplicates(
    filename: str, 
    file_content: bytes
) -> Dict[str, Any]:
    """
    检查文件是否重复。
    
    Returns:
        {
            "is_duplicate": bool,
            "duplicate_type": "filename" | "content" | None,
            "existing_file": str | None,  # 已存在的文件名
            "message": str
        }
    """
```

### 3. 修改上传逻辑

在 `upload_document()` 函数中：
1. 读取文件内容后，先进行重复检测
2. 根据检测结果决定是否继续处理
3. 处理成功后，将哈希值存入 ES

### 4. 新增 API 端点（可选）

```
POST /document/check-duplicates
```
- 用于前端预检查，在实际上传前检测重复
- 支持批量文件检查

## 前端变更

### 上传页面 (`UploadPage.tsx`)

1. 在上传前调用检测接口（可选）
2. 显示重复检测结果：
   - 绿色勾：可以上传
   - 黄色警告：同名文件已存在
   - 红色叉：相同内容已存在
3. 允许用户选择：
   - 跳过重复文件
   - 覆盖已存在文件（如果允许）

### UI 示例

```
┌─────────────────────────────────────────────────────┐
│ 📁 合同文件上传                                      │
├─────────────────────────────────────────────────────┤
│ 待上传文件 (3)                                       │
│ ✅ 新合同A.pdf                     可以上传          │
│ ⚠️  已存在合同B.pdf                同名文件已存在     │
│ ❌ 重复合同C.pdf                   内容与 [XXX.pdf] 相同 │
├─────────────────────────────────────────────────────┤
│ [跳过重复] [覆盖已存在] [全部上传]                    │
└─────────────────────────────────────────────────────┘
```

## 注意事项

1. **哈希计算性能**：SHA256 对大文件计算较快，100MB 文件约 1-2 秒
2. **历史数据兼容**：需要为已上传的文件补充哈希值
3. **批量上传优化**：同批次内部也需要检测重复
